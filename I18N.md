# PriceCheckr multilingual system

Supported locales:
- `en` — English (default)
- `de` — Deutsch
- `fr` — Français
- `es` — Español
- `it` — Italiano
- `nl` — Nederlands
- `pl` — Polski

## How it works

The existing frontend remains the same static/Vercel architecture. No rewrite to Next.js was introduced because the current project is not a Next.js app and replacing the architecture would create unnecessary risk for Stripe, analysis, account state and mobile behavior.

`public/i18n.js` provides:
- browser-language detection on first visit;
- persistent manual selection in `localStorage` under `pricecheckr_locale`;
- locale routes (`/de`, `/fr`, `/es`, `/it`, `/nl`, `/pl`) while English remains `/`;
- English fallback when a locale is unsupported or a translation is missing;
- DOM translation for static and dynamically rendered UI;
- localized placeholders, titles and accessibility labels;
- localized date/number formatting;
- localized legal modal text;
- localized recommendation labels and score labels.

The language selector is present in the desktop header and in the mobile hamburger menu. Selecting a language from the mobile menu closes the menu and updates the locale URL.

## AI analysis

`public/app.js` sends the selected locale to `/api/analyze` as `language`.

`api/analyze.js` validates the locale and explicitly instructs the existing OpenAI analysis request to generate all human-readable assessment fields in the selected language while keeping product names, brands, models, SKUs, retailers, sellers, sources and URLs in their original form.

The recommendation enum remains `BUY`, `WAIT`, `COMPARE`, or `INSUFFICIENT DATA`; the frontend displays a localized label for it.

## Stripe

The existing PaymentIntent/Stripe Elements flow is preserved. The selected locale is passed to Stripe Elements so its supported UI can follow the selected language. No webhook, customer, subscription, payment-intent or premium-access logic was replaced.

## Local testing

For UI-only testing:

```bash
python -m http.server 3000 --directory public
```

Then open:

- `http://localhost:3000/` — English
- `http://localhost:3000/de` — German
- `http://localhost:3000/fr` — French
- `http://localhost:3000/es` — Spanish
- `http://localhost:3000/it` — Italian
- `http://localhost:3000/nl` — Dutch
- `http://localhost:3000/pl` — Polish

For the complete Vercel/API environment, use the project's normal Vercel development workflow with the existing environment variables.

## Production routes

Vercel rewrites each supported locale route to the existing `index.html`, so no duplicate copy of the application is created.

English canonical URL: `/`

Localized routes: `/de`, `/fr`, `/es`, `/it`, `/nl`, `/pl`
